PRIVACY / DATA PRACTICES

Clear about
what leaves the browser.

This policy explains the network data NetRecon processes to run a scan, the external services involved, and what is retained.

EFFECTIVE DATE · NOVEMBER 16, 2026

01 / PROCESSING

Data processed during a scan

When a visitor submits a target, NetRecon processes the entered target, its resolved public IP address or addresses, and the requester's network address for rate limiting. These are used to run the requested DNS, web-posture, geolocation and, when the target matches the deployment's configured scope, TCP checks.

Do not submit credentials, private endpoints, or targets you are not authorised to assess. The application rejects local and non-public address ranges and does not accept embedded URL credentials.

02 / SERVICE PROVIDERS

External services

Depending on the module and deployment configuration, requests may involve these providers:

  • Vercel: hosts the application and may process standard request metadata, including visitor IP address, user agent and operational logs.
  • ipwho.is and ipapi.co: receive the scanned target's resolved public IP address for approximate location, ASN and network-owner lookups. The visitor's IP address is not submitted to these geolocation lookups.
  • Cloudflare Public DNS and Google Public DNS: receive DNS questions needed to resolve target records.
  • jsDelivr: serves the Leaflet map library and stylesheet used by the browser.
  • CARTO and OpenStreetMap: CARTO serves map tiles and OpenStreetMap contributors provide map data attribution. Loading tiles may expose normal browser request metadata and the map tiles requested.
  • Upstash Redis: when the operator configures it, receives rate-limit counter operations associated with the requester IP. It is optional and is used only for shared rate limiting.

Each provider processes information under its own terms and privacy policy. NetRecon does not control their independent retention practices.

03 / RETENTION

Storage and retention

NetRecon does not maintain a persistent database of scan reports. Recent target names are stored in the visitor's browser local storage so they can be reused in the interface. Clearing browser site data removes that local history.

The geolocation module may cache lookup results temporarily. Process-local rate-limit counters expire after their 60-second window. When Upstash is enabled, its rate-limit keys use a short expiry. Hosting-provider operational logs may be retained under the hosting provider's own policies.

04 / SECURITY

Protective controls

  • Public target validation blocks private, loopback, link-local, CGNAT, reserved and internal destinations.
  • Active TCP probing starts only for targets that match the server-side scope configured by the deployment operator.
  • Scan requests are rate limited. Deployments can use Upstash for a shared counter across instances.
  • Scan modules handle failures independently so one unavailable provider does not require fabricated data or a false location marker.

05 / CONTACT

Questions and requests

For privacy or security questions, open an issue in the NetRecon GitHub repository.

This policy should be reviewed whenever the deployment's external providers or data handling change.
