This policy explains the network data NetRecon processes to run a scan, the external infrastructure providers involved, and what is retained.

EFFECTIVE DATE: NOVEMBER 19, 2026

01 / PROCESSING

Data processed during a scan

When a visitor submits a target, NetRecon processes the entered target, its resolved public IP address or addresses, and the requester IP address for rate limiting. These are used strictly to execute DNS, TLS, HTTP header, IP geolocation, and operator-scoped TCP checks.

Do not submit credentials, private endpoints, or targets you are not authorized to assess. The server blocks private, loopback, link-local, CGNAT, reserved, and internal hostnames and rejects embedded URL credentials.

02 / SERVICE PROVIDERS

External services

NetRecon renders its 3D tracking globe locally in the browser using HTML5 Canvas with zero third-party map tiles, CDN scripts, or external web fonts. Server-side scans may involve these providers:

  • Vercel: hosts the application and may process standard HTTP request metadata, including visitor IP address, user agent, and operational logs.
  • ipwho.is and ipapi.co: receive the scanned target resolved public IP address for approximate geolocation, ASN, and network-owner lookups. Visitor IP addresses are not submitted to geolocation providers.
  • Cloudflare Public DNS and Google Public DNS: receive DNS queries required to resolve target records and reverse PTR lookups.
  • Upstash Redis: optional shared rate-limit counter storing window-bucketed requester IP counters when configured by the operator.

Each provider processes data under its own terms and privacy policy.

03 / RETENTION & LOCAL STORAGE

Storage, cookies, and deletion

NetRecon sets no tracking cookies and maintains no persistent database of scan reports. Recent target names are saved only in browser localStorage so you can re-run queries quickly; clearing browser site data deletes them immediately.

In-memory geolocation caches expire after 15 minutes. Rate-limit counters expire after their 60-second window. NetRecon is a technical security utility not directed at children under 13.

04 / SECURITY CONTROLS

Protective architecture

  • Pinned-socket HTTPS and HTTP probing with strict public IP validation prevents DNS rebinding and SSRF redirects.
  • Active TCP probing runs only when the target matches the server-side NETRECON_ACTIVE_SCAN_ALLOWLIST configuration.
  • Strict self-only Content-Security-Policy blocks third-party scripts, frames, and external tile calls.

05 / CONTACT

Questions and rights
